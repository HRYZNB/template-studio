# RuiWare 单体零部件模板平台：开发交接与页面功能说明

> 适用对象：后续前端、后端、CAD/规则引擎开发人员，以及负责验收模板的工程师。  
> 当前版本：2026-08-14。本文以源码实现为准；旧的内置 AI 协作已移除，外部协作通过本地 MCP 进行。

## 1. 平台定位与边界

RuiWare 是“**单体零部件模板**”的工程编辑器。它的输出不是一次性的零件模型，而是包含参数、草图、几何配方、制造规则、接口、验证记录和 CAD 产物的可复用模板版本。

平台固定使用 `templateKind = monolithicPart`：一个零件最终必须是一个连续实体。焊接组合件、多个独立实体、装配配对关系不在本平台建模；它们属于未来组件/装配层。

核心原则如下：

1. **稳定 ID 优先于显示名称**：规则、表达式和下游系统引用参数 ID、图元 ID、语义面 ID 和规则 ID；中文名称仅供阅读。
2. **数据先于预览**：二维和三维视图必须由统一元模型和求解/编译结果驱动，不能成为另一份可编辑真值。
3. **规则生成实例，而非复制几何**：孔、槽和切口由规则在实例化时展开；避免维护一串随长度变化而失效的几何节点。
4. **修订不可覆盖**：保存、完成阶段、应用提案和发布都会产生或引用不可变修订，防止下游设计被静默改变。
5. **确定性验证**：草图求解、规则求值和 OpenCascade B-Rep 编译是准入依据；页面上的“已复核”仅表示工程责任确认，不能替代计算。

## 2. 运行、目录和职责分工

| 区域 | 主要文件 | 职责 |
|---|---|---|
| Studio 前端 | `apps/studio-web/src/App.tsx`、`api.ts`、`types.ts` | 七阶段工作台、草图交互、表单与调用 API |
| 模板 API | `services/template-api/app/main.py` | 草稿/修订、附件、阶段验证、求值、编译、发布、结构化提案接口 |
| 领域元模型 | `libs/python/template_core/` | 参数、草图、几何配方、规则、接口、变体、校验与 lowering |

## 3. 总体工作流及为什么分为七页

```text
定义 → 材料 → 几何 → 规则 → 契约 → 验证 → 发布
```

这不是普通表单的视觉分页，而是有依赖关系的工程阶段：材料决定厚度域，几何定义语义面，规则引用语义面和参数，接口可继承规则实例，验证检查整个模板，发布冻结验证通过的版本。前一阶段发生实质改动时，后续阶段的完成状态会失效，必须重新确认。

### 3.1 全局顶部栏、左侧栏和通用动作

| 位置/按钮 | 做什么 | 为什么这样做 |
|---|---|---|
| 左上“+” | 新建空白单体零部件模板 | 以受控默认元模型开始，避免复制历史草稿后遗留错误引用。 |
| 模板选择器 | 切换当前草稿 | 只切换编辑上下文，不隐式保存当前改动。 |
| “副本” | 复制当前模板为新草稿 | 适合派生相似零件；源模板和已发布版本不被改动。 |
| “归档” | 归档当前草稿（需确认） | 从日常列表移除废弃草稿，同时保留审计数据。 |
| “保存修订” | 将当前未保存内存状态写为新修订 | 不覆盖旧修订，保证 CAD 产物和版本可追溯。按钮在无修改或忙碌时禁用。 |
| 左侧七个阶段按钮 | 跳转至任一阶段 | 允许回看和修订；状态色显示是否已完成，但不能绕过后端阶段校验。 |
| `.rwpart` 下载图标 | 下载当前模板源包 | 将元模型、规则、接口、验证资料交给下游或归档，而非只交 STEP。 |
| “阶段检查” | 对当前阶段运行只读校验 | 让工程师先看缺失项和风险，不产生状态变化。 |
| “检查并继续” | 校验当前阶段；通过则标记完成并跳到下一阶段 | 将“检查”和“承诺完成”分开，避免因临时浏览而误完成。验证/发布页使用其专属确认动作。 |
| 右侧“阶段准入”卡 | 显示校验清单、进度和诊断 | 把页面输入与实际准入条件并列，避免仅凭视觉判断“填完了”。 |
| 提示/错误消息右侧关闭按钮 | 关闭当前提示 | 错误会自动消失；关闭仅影响界面，不会撤销操作。 |

## 4. 页面 01：定义（需求与证据）

### 4.1 目的

定义页回答“这是什么、按什么工艺制造、证据来自哪里”。它不直接画几何，因此设计意图不会被某个即时尺寸锁死。后续阶段从这里的制造分类和初始原型获得受控选项。

### 4.2 模板身份

| 控件 | 做什么 | 设计原因 |
|---|---|---|
| 模板编码 | 输入并自动转为大写 | 编码是业务身份和发布版本索引，统一大小写避免重复。 |
| 模板名称、负责人、组织 | 记录可读身份与责任归属 | 便于检索、审查和版本交接，不参与几何表达式。 |
| 检索标签 | 用逗号分隔业务叫法、应用/制造分类 | 支持检索，不让标签承担结构化规则的职责。 |

### 4.3 单体制造分类

| 控件 | 做什么 | 设计原因 |
|---|---|---|
| 零部件来源 | 从注册表选择来源 | 限定受控分类，不允许任意文本造成下游分类漂移。 |
| 主成形工艺 | 选择冷弯、切割、机加工等主路线 | 用于筛选适用算子和可制造性规则。 |
| 后续工序复选项 | 选择多个二次工序 | 一个零件可同时有冲孔、表处等工序，因此不使用单选。 |
| “制造分类与单体范围已由工程师确认” | 人工复核开关 | 明确确认没有把组件/焊接件错误放进单体模板范围。分类变更会自动取消复核。 |

### 4.4 初始几何原型

原型卡（平板、开口薄壁、闭口型材、回转体等）用于初始化草图模式、驱动参数和首个几何算子。点击卡片会更新这三项，但**不会删除**制造规则、接口或变体；因此已完成详细建模后不应随意切换。卡片上的“可直接编译 / 需配置 / 规划中”来自注册表，避免 UI 承诺 CAD 内核尚未实现的能力。

### 4.5 设计意图与证据

| 控件/按钮 | 做什么 | 设计原因 |
|---|---|---|
| 用途说明 | 描述零件使用位置和功能 | 为参数、接口和验证提供工程语义。 |
| 设计约束与可变范围 | 记录必须保持的规律、允许变化范围、限制 | 规则应来自设计意图，而不是藏在前端代码里。 |
| “添加多张图片、图纸或已有 CAD” | 上传 PNG/JPG/WEBP/PDF/DXF/DWG/STEP/STP 等附件（单个 ≤20 MB） | 附件作为证据和追溯资料，**不直接成为权威几何**。 |
| 每项“图片/证据说明” | 编辑后失焦保存元数据 | 让图纸中的已知尺寸、视图方向和假设可被审查；图片本身不含可靠语义。 |
| 附件删除图标 | 删除该附件记录 | 用于移除错误或重复证据；删除前应确认不再被导入草图引用。 |

## 5. 页面 02：材料（适用范围、毛坯与验证）

### 5.1 材料适用范围

该区定义“模板允许什么材料”，不是给某一次实例固定材料。厚度域会同步约束 `thickness` 参数、材料筛选与边界用例。

| 控件/按钮 | 做什么 | 设计原因 |
|---|---|---|
| 宽泛类别 / 受控材料族 / 唯一指定材料 | 选择材料约束强度 | 类别适合允许替代的通用件；材料族增加牌号/标准约束；唯一记录用于严控零件。 |
| 供应材料形态 | 选择卷材、板材、型材、管材等 | 连接材料库业务类型与后续毛坯/工艺判断。 |
| 允许厚度值、下限、上限 | 输入离散规格和/或连续边界 | 实际域取二者交集，避免“列表允许但范围禁止”的矛盾。输入框失焦或回车时提交离散规格。 |
| 厚度驱动参数 | 指定受材料控制的参数 ID | 将材料选择与几何厚度建立明确、可检查的契约。 |
| 材料族标签、牌号、标准、表面 | 材料族模式下追加筛选条件 | 仅在有意义时显示，减少宽泛类别下的无效配置。 |
| “允许实例选择满足条件的材料” | 允许实例化时在合格候选中选择 | 唯一指定材料时禁用，防止逻辑自相矛盾。 |
| “工程师已确认材料边界” | 确认范围已评审 | 任何材料边界改动都会取消已有验证样例的复核。 |

### 5.2 供应材料与毛坯准备

| 控件 | 做什么 | 设计原因 |
|---|---|---|
| 毛坯准备关系 | 选择“与供应材料一致”或“需要毛坯准备” | 区分采购状态与实际进入主体工序的初始几何。 |
| 制造起始毛坯 | 选择带料、板坯、型材段、管段等 | 让工艺规划和下游成本系统获得真实起点。 |
| 主体制造路线 | 选择冷弯、激光、机加工、挤压、折弯等 | 与定义页工艺互相校验，而不是代替定义页的分类。 |
| 毛坯准备工序复选项 | 勾选开卷、校平、分条、锯切等 | 仅在“需要毛坯准备”时出现，避免把不适用工序写入模型。 |
| 长/宽/厚表达式与余量 | 定义毛坯尺寸如何由模板参数计算 | 将制造余量显式化，不把余量混入成品尺寸。 |

### 5.3 材料验证矩阵与材料库

| 按钮/控件 | 做什么 | 设计原因 |
|---|---|---|
| 最小、标称、最大、特殊样例卡的“选择材料” | 选择当前目标槽位 | 标称样例用于当前 CAD 编译；边界/特殊样例用于回归，不改变适用范围。 |
| 样例“已复核” | 标记该具体材料组合已检查 | 将“材料范围正确”和“样例已验证”分开。 |
| 样例“移除” | 移除非必要样例 | 避免过期样例影响准入；标称用例按校验要求保留。 |
| 目标槽位下拉 | 指定搜索结果绑定到哪个样例 | 可连续选择不同材料，无需反复打开卡片。 |
| “仅显示符合要求” | 过滤材料库搜索结果 | 默认降低误选风险；取消后可查看不匹配原因。 |
| 搜索/回车 | 按牌号、名称、标准查询材料库 | 材料库只读接入，模板不直接改库。 |
| “动态引用” | 保存材料库记录引用 | 后续材料库更新可被发现，适合受控持续维护。 |
| “冻结快照” | 把材料属性复制到模板样例 | 保证历史编译可重现，适合发布基准。 |

## 6. 页面 03：几何（草图、设计意图、配方与语义面）

### 6.1 统一语义参数轮廓

三种来源按钮均最终进入同一个 `semanticProfile` 模型：

| 按钮/控件 | 做什么 | 设计原因 |
|---|---|---|
| 交互绘制 | 创建手工语义草图 | 最直接的可编辑来源。 |
| 导入轮廓 | 上传 DXF/DWG/SVG/STEP 等证据并填写单位、比例 | 导入文件只作为转换来源，必须转成语义图元，避免 CAD 图元编号成为隐式依赖。 |
| 复用受控截面 | 填写受控截面 ID 后复制为当前草图 | 保留来源可追溯性，同时使本模板拥有独立、可参数化的草图。 |
| “来源已转换为语义草图并复核” | 确认导入/复用内容已脱离外部图元编号 | 防止把未清理的外部引用误当成发布级几何。 |

### 6.2 二维参数化草图画布

| 按钮/交互 | 做什么 | 设计原因 |
|---|---|---|
| 最小 / 标称 / 最大 | 切换要查看的求解工况 | 同时验证参数边界，而不是只看标称图形。非标称工况禁止直接拖拽，避免把边界结果写回草图。 |
| 选择、点、直线、矩形、圆、圆弧 | 选择画布工具并创建相应语义图元 | 覆盖当前稳定的直线/圆/圆弧建模能力。 |
| 撤销 / 重做 | 在当前会话回退或重放草图编辑 | 降低细节编辑风险；保存后仍以修订历史为审计依据。 |
| 移动 / 复制 / 删除 | 对选中图元操作 | 仅标称工况可操作；复制同步复制内部约束和区域引用，删除同步清理失效引用。 |
| 缩小 / 放大 / 适合 | 控制画布视图 | 只改变视图，不改变草图坐标。 |
| 偏移 ΔU/ΔV | 指定移动/复制距离 | 使用当前草图平面局部轴，避免把屏幕坐标误作工程坐标。 |
| 画布点击、Shift/Ctrl 点击 | 单选/多选图元 | 多选用于批量编辑、建立约束与区域。快捷键：Delete 删除、Ctrl/Cmd+D 复制、Esc 取消选择。 |

### 6.3 当前对象、草图设计意图和模式切换

| 控件/按钮 | 做什么 | 设计原因 |
|---|---|---|
| 截面建模模式 | 单闭合区域、多环/多腔、中心线+厚度薄壁 | 明确材料区域如何被解释为实体；同一线框在不同模式下含义不同。 |
| 弹窗“仅切换解释” | 只改变模式，保留图元/尺寸 | 适合工程师自己迁移既有草图。 |
| 弹窗“重建推荐图形” | 替换图元、约束、尺寸和区域 | 适合原拓扑不适合新模式；清理旧约束避免残留拉扯。 |
| 截面所在平面 | 选择 XY/XZ/YZ | 决定三维法向，二维尺寸与拓扑不变。 |
| 稳定 ID | 改图元 ID，并同步约束/区域引用 | ID 是持久契约，改名必须级联，不能只改显示文本。 |
| 图元名称、构造图元、端点/圆心/半径 | 编辑语义和几何 | 构造图元不参与材料区域，可用于约束和定位。 |
| “删除图元及其失效引用” | 删除当前选择并清理依赖 | 避免保留指向不存在图元的约束或区域。 |
| 草图设计意图页签：图元/约束/尺寸/区域/诊断 | 编辑设计语义、建立约束、绑定参数、定义加减材闭合区、查看问题 | 将几何绘制和设计意图分开，便于维护。各页的新增/删除按钮均只改草图草稿；“约束已复核”确认后才满足阶段要求。 |

### 6.4 几何配方与语义面

| 按钮/控件 | 做什么 | 设计原因 |
|---|---|---|
| “添加算子” | 在配方末尾增加一个几何算子 | 让实体构造按明确顺序表达，避免从 UI 猜测特征树。 |
| 构造方式、草图引用、路径引用 | 定义配方整体语义 | 支持拉伸、回转、扫掠、放样、钣金等；可用性由算子状态控制。 |
| 算子类型下拉 | 选择具体 CAD 算子并加载默认参数 | “待实现”算子禁用，防止产生无法发布的配方。 |
| 回转/扫掠/放样/折弯专属字段 | 编辑各算子的轴、路径、站点或折弯参数 | 防止把结构化参数塞进无语义的通用文本框。 |
| 参数表达式、条件 | 以参数 ID/表达式控制算子 | 将可变性放在配方中，保持同一模板可实例化。 |
| 删除算子 | 移除该算子 | 会改变后续引用，删除后必须重新检查配方。 |
| “新增语义面” | 新增稳定的制造特征定位面 | 特征和接口引用语义面 ID，而不引用易变的 B-Rep 面序号。 |
| 语义面的 ID、名称、局部坐标系、U/V 起点和跨度 | 定义面上的局部定位契约 | 孔距、端距和阵列可在 U/V 中稳定表达，再由 `hostFrame` 映射到 CAD。 |
| 删除语义面 | 删除该面 | 之后引用它的规则/接口会在校验中报错，必须一并修正。 |
| “几何配方已复核” | 工程师确认算子顺序、引用和条件 | 人工确认补充计算校验，改配方后应取消确认。 |

## 7. 页面 04：规则（制造特征生成）

页面用于定义孔、槽、矩形/多边形切口如何在实例上生成。规则可绑定多个语义面，在每个面上展开稳定特征实例。

| 按钮/控件 | 做什么 | 设计原因 |
|---|---|---|
| “新建规则” / “创建第一条规则” | 新增默认制造规则 | 无孔零件可保持空；有重复孔或切口时必须用规则，而不是手工复制几何。 |
| 启用开关 | 暂时让一条规则不参与求值 | 便于诊断或保留历史规则，不必马上删除。 |
| 删除图标 | 删除整条规则 | 同时影响特征派生接口，删除后须重新检查契约。 |
| 规则名称、特征类型 | 设置圆孔、直槽、矩形切口、直线多边形切口 | 使用明确特征语义，CAD lowering 才能稳定执行。 |
| 目标语义面复选项 | 将规则绑定到一个或多个面 | 支持同一孔逻辑跨多个面，不再维护模糊“宿主面”。 |
| 布置方式 | 单项、线性阵列、两端均布、最大间距、对称阵列 | 覆盖固定数量与随长度变化数量的典型制造逻辑。 |
| 布置轴 | 选择语义面局部 U 或 V | 用局部轴表达孔行方向，避免依赖全局 XYZ。 |
| 数量/间距/首端距/终端距/最大间距表达式 | 输入常量、参数 ID 或表达式 | 允许实例填写 `holePitch`，也允许它由公式派生；两端距离在均布/最大间距模式中是独立参数。 |
| “创建可填写间距参数” | 新建并绑定公开实例参数 | 把布置需求直接转成可填写参数，减少手工跨页建参。 |
| 生效条件 | 例如 `length >= 1800 and hasServiceHole` | 使特征随实例条件出现/消失，而不是制作多份几何模板。 |
| 展开安全上限 | 限制最大实例数 | 保护 CAD 和规则引擎，避免错误表达式生成成千上万特征。 |
| 非多边形特征的常量/表达式切换、删除参数项 | 管理孔径、U/V 位置、槽宽等 | 区分固定设计值与由契约参数驱动的值。 |
| 多边形“绑定已有参数/创建可填写尺寸参数” | 给轮廓局部尺寸绑定模板参数 | 固定轮廓不必绑定；只有希望形状随实例变化时才建立契约。 |
| 参数化矩形/梯形/L 形 | 生成可编辑的直线轮廓顶点预置 | 提升常见切口定义效率，同时所有边仍是直线。 |
| 顶点 U/V、添加顶点、删除顶点 | 编辑闭合直线多边形 | 顶点按顺序自动闭合，至少三点；引擎会拒绝退化和自交。 |
| 规则局部预览 | 显示可求值轮廓/尺寸 | 仅作辅助，不代替实例试算；表达式未知时明确显示不可预览。 |
| “制造特征规则已复核” | 确认规则逻辑 | 规则改动后应重新复核并在契约页试算。 |

## 8. 页面 05：契约（参数、接口与试算）

该页有三个页签，它们共同定义模板如何被实例化、如何供未来装配使用、以及如何验证参数变化。

### 8.1 参数契约

| 按钮/控件 | 做什么 | 设计原因 |
|---|---|---|
| “新增可填写实例参数” | 创建公开的 `userInput` 参数 | 用于尺寸、孔距、切口尺寸等实例差异。 |
| 稳定 ID | 编辑参数变量名；失焦时校验并级联改写引用 | 表达式和规则依赖 ID，允许中文显示名但禁止用显示名作为机器引用。 |
| “公开” | 控制实例输入参数是否出现在实例表单 | 只有 `userInput + partInstance` 可以公开，其他来源不能被实例任意覆盖。 |
| 显示名称 | 编辑面向工程师的名称 | 可修复乱码或改业务术语而不破坏表达式。 |
| 类型 | 数值、整数、布尔、枚举、文本 | 类型决定默认值编辑器、范围和合法性；不再把所有默认值强制当数字。 |
| 默认/标称值、数值范围 | 定义实例初值和允许域 | 是下游缺值回退与边界验证的基础。 |
| 枚举选项“添加/删除” | 逐项维护枚举，不使用逗号分隔 | 避免逗号输入法和空字符串导致的歧义；至少保留一项。 |
| 来源 | 选择实例输入、公式、材料属性、查表、组件/产品/项目区等 | 明确值的责任边界。实例输入/常量不需要引用路径；公式需要表达式；上游来源需要点号路径。 |
| 派生公式/上游数据路径 | 录入 `length / 300`、`material.thickness` 等 | 可静态检查依赖和来源，避免隐藏在备注中的计算逻辑。 |
| 删除参数 | 删除非核心参数 | 长度、宽度、厚度等核心参数禁用删除；删除前须先解除规则/接口引用。 |

### 8.2 零部件接口

接口只描述“本零件提供什么稳定几何基准”，不描述另一零件、配对 ID、装配偏移或配合关系。

| 按钮/控件 | 做什么 | 设计原因 |
|---|---|---|
| “新增接口” | 创建默认定位接口 | 以稳定接口 ID 声明未来组件/装配可消费的基准。 |
| 接口名称、类型 | 设置定位、连接、支承、可调、工艺基准等 | 让未来系统按意图筛选，避免只有没有语义的点/面列表。 |
| 声明方式：静态几何 / 制造特征派生 | 选择接口来源 | 静态接口绑定固定语义面；派生接口随孔/切口规则实例数自动增减。 |
| 来源制造特征规则 | 为派生接口选择规则 | 立柱长度增加孔数时，接口实例会同步增加，无需手工维护。 |
| 参考轴、参考原点、关联几何面 | 定义静态接口局部坐标框架 | 提供稳定几何参考，不依赖 CAD 临时拓扑编号。 |
| 定位方式、定位角色 | 描述面贴合/同轴/销孔等及主次第三定位 | 用于表达本零件内部定位层次，不等同于装配配对。 |
| 兼容标签、相关参数 | 填写未来筛选标签与影响尺寸的参数 | 保持可扩展性，但不在单件层错误实现装配映射。 |
| “关键接口”“工程师已复核” | 标记准入重要性和责任确认 | 将普通装配提示与必须满足的关键基准区分。 |
| “删除接口” | 删除该接口声明 | 不删除底层几何或制造规则；下游消费者需要重新处理。 |

### 8.3 试算与验证

| 按钮/控件 | 做什么 | 设计原因 |
|---|---|---|
| 当前实例参数输入 | 覆盖公开参数进行临时试算 | 不改模板默认值，方便快速检查一个订单/规格。 |
| “保存并运行规则求值” | 必要时先保存草稿，再解析参数、规则和接口 | 确保试算针对有修订号的工程真值；结果显示特征、接口实例、求值顺序和诊断。 |
| “保存当前” | 将当前覆盖项保存成验证用例 | 把一次临时试算升级为可重复的回归案例。 |
| “+ 最小边界”“+ 最大边界” | 基于公开参数范围自动创建边界用例 | 用于捕获孔数阈值、尺寸域和材料边界问题；创建后仍需判断组合是否工程合理。 |
| “+ 回归用例” | 创建空的可命名回归案例 | 用于复现历史缺陷或特殊订单组合。 |
| 每个用例的“试算” | 将该用例覆盖项带入当前实例并运行 | 使保存的案例成为实际可执行验证，而非备注。 |
| 用例删除图标 | 删除非 `nominal` 用例 | 标称用例是基础准入对象，不允许删除。 |

## 9. 页面 06：验证（确定性 B-Rep 编译）

| 按钮/控件 | 做什么 | 设计原因 |
|---|---|---|
| “运行 B-Rep 编译” | 将规则先展开为静态计划，再调用 OpenCascade 生成实体、STEP 与 STL | 证明模型不只是表单合法，而是 CAD 内核实际可生成单实体。 |
| 三维查看器 | 查看 STL 预览，拖拽旋转、缩放、平移 | 仅用于人工检查；STEP/B-Rep 才是权威。 |
| 指标与诊断 | 显示编译状态、有效性、实体数、体积、算子数和问题代码 | 帮助定位几何、规则、材料或算子问题。 |
| 验证产物下载项 | 下载 STEP、STL、静态计划、诊断、语义映射等 | STEP 供制造/下游使用，其余文件用于复现与审计。 |
| “确认几何审查” | 编译成功后完成验证阶段 | 不能在编译失败、无产物或服务忙碌时点击，避免无 CAD 依据的发布。 |

## 10. 页面 07：发布（准入与版本）

| 按钮/控件 | 做什么 | 设计原因 |
|---|---|---|
| 复核人 | 填写发布责任人 | 发布不仅是技术动作，还需要可追溯责任。 |
| 发布通道 | 选择开发、试用或生产 | 允许同一模板在不同治理等级下流转。 |
| 版本说明 | 记录变更、适用范围和已知限制 | 为使用者和审计提供版本差异上下文。 |
| “发布模板版本” | 在全部阶段通过、存在有效 CAD 且未发布当前修订时冻结版本 | 生成不可变版本，后续编辑必须形成新修订，避免影响已完成设计。 |
| 历史版本“下载” | 下载该版本关联的源包 | 保证下游始终能取回与当时发布一致的定义和产物。 |

## 11. 外部 MCP 协作（非平台页面）

平台不再内置模型地址、密钥、聊天窗口或“图片发给模型”的开关。需要由 Codex 等外部客户端通过本地 stdio MCP 工作：

| 工具 | 是否写入 | 用途 |
|---|---:|---|
| `ruiware_get_draft_context` | 否 | 读取模板完整工程上下文。 |
| `ruiware_get_attachment` | 否 | 读取一项证据元数据与受控地址。 |
| `ruiware_solve_sketch` | 否 | 运行最小/标称/最大草图求解。 |
| `ruiware_preview_proposal` | 否 | 在临时副本中预览结构化修改、差异和校验。 |
| `ruiware_submit_proposal` | **是** | 在用户明确确认后应用提案并创建新修订。 |
| `ruiware_get_validation_result` | 否 | 读取某阶段校验结果。 |

写入工具不应由代理自动调用。正确流程是：读取上下文 → 生成结构化提案 → 预览 → 人工确认 → 提交 → 再次校验/编译。MCP 启动配置见 `services/ruiware-mcp/README.md`。

## 12. 后端行为、维护约束与常见误区

### 12.1 API 行为

- 草稿保存、阶段完成、结构化提案应用和发布均会生成/引用修订；API 会检查修订冲突。
- `POST /api/v1/template-drafts/{id}/proposals/preview` 不保存；`.../proposals/apply` 才保存。
- 附件使用受控上传目录和哈希；前端不能把本地路径当作平台数据。
- 材料库在本平台是读取与绑定，不在模板编辑器中直接修改。
- 旧草稿中的已移除 `aiAssisted` 草图来源会兼容迁移为 `manual`；新 UI 不再提供该选项。

### 12.2 不应破坏的契约

1. 不要把稳定 ID 改成用显示名称引用；重命名必须调用/复用级联改写逻辑。
2. 不要以 B-Rep 面索引取代语义面 ID；拓扑重建会改变面序号。
3. 不要在前端模拟规则结果后直接当真；必须调用后端 `evaluate` 或编译。
4. 不要让“工程师已复核”绕过表达式、草图或 B-Rep 校验。
5. 不要将 MCP 写工具改为无确认的自动动作。
6. 不要把未实现算子显示为可发布；算子注册表、lowering、CAD worker 和校验必须同步扩展。

### 12.3 已知范围

当前稳定几何基线是直线/圆/圆弧草图、多环区域拉伸、连续直线中心线薄壁拉伸，以及圆孔、直槽、矩形/直线多边形切口。样条 B-Rep、中心线圆弧偏置、任意扫掠、通用放样和复杂钣金还不是稳定发布能力；UI 应继续明确禁用或标注未实现状态。

## 13. 建议的开发与验证流程

1. 修改 `template_core` 元模型或规则后，先补模型/规则单元测试。
2. 修改 API 后，补充 FastAPI 路由测试，尤其是修订冲突、预览不写入、应用写入和阶段失效。
3. 修改页面后执行 TypeScript 检查与生产构建。
4. 涉及 CAD lowering 或 worker 时，至少覆盖一个最小、标称、最大实例并检查 STEP 产物。
5. 最后运行完整回归：

```powershell
.\.venv\Scripts\python.exe -m pytest -q
bun --cwd apps\studio-web run build
```

本文与 `CONVERSATION-HANDOFF.md`、`docs/DEVELOPMENT.md`、`docs/UNIFIED-METAMODEL.md` 配套使用：本文解释页面行为和产品理由，后两者用于查找代码与元模型细节。
